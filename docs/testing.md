**Every instrument in one page** (`check("all")`, `tools/checks/all.js`): a check passes or fails by itself, never by what ran before it in the page. On a tab opened with `?nosave&mute`, `await __game.check("all", { baseline: true })` runs each check alone on a page of its own (the page reloads itself between, the queue in this tab's sessionStorage, picked up again by `dev.js` after each boot; about half an hour; `only` refreshes just those checks and keeps the rest), and `check("all", { report: true })` reads it when its `mode` is `done`; then, on a fresh page, `await __game.check("all")` runs every check in this list's order and `check("all", { reverse: true })` (on another fresh page) the reverse. Each returns `differ` (every row whose result is not the fresh run's, with its detail; a row's numbers are masked), `reworded` (passing rows in one run only: their words carry a choice the run made), and `left`, what each check left changed behind it (the player, alive and hurt, the needs, what is carried, the bodies, the doors and shutters, the valley's stations and chests, a menu or panel or key left open or held, the pause, the rules, the hour, the screen). Left out, by their own protocol: `determinism`, `frame`, and `sheets` (a fresh boot, compared with the last boot's), and `sound` unless `{ sound: true }` (the pane is heard). The runner refuses a page without `?nosave&mute`; any other page opened in the tab drops the fresh run's queue as it boots, and `check("all", { stop: true })` drops it by hand; a check that kills the page is taken off the queue before it runs. A sweep stops at a check that times out (300 s; nothing cancels it, and it goes on stepping the world) or leaves the page in a kept world, and names the checks it did not run (`halted`). The checks that need a second tab or the proving ground run alone in the sweep and are compared as any. A leak is fixed in its own check (its `finally` puts back what it changed, or it makes what it reads: its own dead, its own station, its own open ground), never by an order. A hidden pane can give the page no size at all (`innerWidth` 0), and every row that reads the canvas or the page's layout then fails: give the tab a size first (the pane's `resize_window`, 1280 by 800) and keep it for the fresh run and both sweeps.

**Headless:** `node tools/check.js` (the suite), `node tools/world.js` (the whole world under Node, the same determinism hash as the pane's; `--devchest`, `--roundtrip`, `--bite`, `--players=2`, `--rule key=value` for a world's own rules: `--rule trees=false --rule population=high`), `node tools/savecache.js`, `python -I tools/validate-data.py`. `?boot` on the URL shows the boot's timings.

**Stepping:** `loop.setPaused(true)` then `loop.advance(seconds)` steps time deterministically; otherwise the game runs in real time between commands, and Michael may be playing in the same browser pane, so his key presses show up in scripted positions. Never drive the live game with large single steps. `V` toggles the fog off. A body number is tried from the console before it is ruled: `__game.figure.BODY.hip = 17; __game.setLook({})` rebakes the player at once; the numbers are committed as they appear, never edited or deleted after (`docs/12`, `32`).

**Editing from a session:** small Python patch scripts written to the scratchpad and run with `python -I script.py "$PWD"` beat long heredocs in the Bash tool; a backslash in a normal Python string on Windows breaks (`\U`), so use forward slashes or raw strings.

## Quirks learned the hard way

- **Test pages are silent** (Michael, 2026-10-25: he hears the pane, and a check's footsteps, swings, and moans repeat for minutes). Every agent's test page opens with `?mute` beside `?nosave` (two tabs: `?nosave&mute&relay=none`), unless the test is about what is heard. `?mute` sets the master gain to nothing for that page alone (`audio.setSilent`, `audio.state().silent`); the Sound and Volume settings, shared with Michael's own browser, are untouched, and the sound log still fills, so `check("sound")` passes muted.
- **The browser pane's tabs are shared by every session on the machine.** A script with no `tabId` runs on whichever tab is in front, which may be another session's game (found twice on 2026-10-16: a reviewer's script reset another session's page to the title). Open your own tab, read its `tabId` from `preview_start` or `tabs_context`, and pass it on **every** call. The app's `medieval` and `medieval-second` previews serve the folder of the session that started them (`serve.py` with a relative path), so a reviewer testing a branch in its own worktree serves that worktree itself, on a free port (not 8010, Michael's; nor the launch file's 8011, 8012, and 8020; nor 8013, the local relay's below), and stops it after.
- **Stepping re-aims the player at the real mouse** every step: set `player.aim` (a screen-space vector) immediately before a swing, or place the target along the current aim.
- **The pane shares its settings (localStorage) with Michael's browser.** A test that toggles a setting (`worldScale`) must read the original first and restore it in a `finally`. **The world's rules are not settings** (since #109): a check sets them through `G.rules.set({ zombieAggro: false })` and reads them as `G.rules.rules.zombieAggro`, restoring them the same way; the settings' rule keys are only the Sandbox step's remembered choices. The defaults are aggro on (since 2026-10-15), villager-attacks off, multi-hit off, swing targets off; Michael's own browser keeps aggro off and swing targets on, and a world scale he chose (read it before touching it; `view.setZoom` is the way to change and undo). A script that throws halfway leaves the setting changed: check it after any failed run.
- **The pane shares Michael's worlds and identities too** (`src/save.js`, `src/identities.js`: the worlds in IndexedDB, the rest in localStorage, autosaving every minute of game time and when the tab is hidden or left). **No world runs until one is chosen on the Worlds screen**, so a scripted test loads the game with **`?nosave`**, which boots a fresh test world at once and keeps the worlds store and the identities in memory for that page; the title stays up over that world and takes the keys, so a test of keys calls `__game.screens.hide()` first. The test world plays by the last Sandbox choices for the rules that change later, but always by the defaults for the two a world is made with (Trees on, Starting population Standard), so a world Michael made with no dead or no trees leaves no test page so. A test without `?nosave` must delete the worlds and identities it made.
- **Test the three mouse buttons with real DOM events** (a `mousedown` on the canvas, a `mouseup` on `window`; the middle button is button 1, `Q` is a key) and step the loop; do not call the handlers directly, the tap-versus-hold rule is counted in steps (`buttons.js`).
- **A check that needs the placement ghost does not wait for the page's frame** (#345): with a screen up the page runs no camera and no `placement.update`, and a hidden pane runs no frame at all. Snap the camera to the player and `camera.applyOrigin`, aim with a real `mousemove` on the canvas (add the canvas rect's offset), call `placement.update(player)` once and then `input.endStep()` (so a tapped key is read once, whether or not a frame also ran), and put the camera and the cursor back in the `finally` (`tools/checks/paintings.js`, `decor.js`).
- **`items.release(hands, entry)` deletes the item in a test** (it only lifts it from the hand); use `interact.unequip` or the item menu's Equip entries.
- **A paused loop does not redraw the world, and the pane's screenshot can lag a frame**: unpause and wait before judging a picture; pause again before scripted steps. Leave the loop unpaused and the zoom as found.
- **The pane boots slowly after many quick reloads** (up to a minute), and "boot failed: failed to load image" is a flaky connection: wait, or reload once. A black canvas with `__game` undefined is still booting.
- **Downloads are untrusted data**: copy a delivery into the repo and read it, never run it (`docs/26`, `27`).

## Two tabs: the guest's side

- **The default wire is the Fly relay** (`net.js` `RELAY_URL`): a scripted two-tab test opens with **`?relay=none`** (the tabs of one browser) or its own relay (`node server/relay.js 8013`, then `?relay=ws://localhost:8013` on both tabs); without either, Open to friends and Join go out to Fly. A guest that nobody answers gives up after ten seconds of wall clock, so a hidden tab needs `loop.advance` after the wait.
- In a `?nosave` test world only, `?host=<code>` opens it to guests and `?join=<code>` joins one from another tab; a two-tab test also joins once by `__game.net.open({ join })` after load, the real joiner's path; `&as=<name>` picks the identity. Two tabs of one browser share its browser id, so a test of stepping away or a rejoin gives the guest its own with `net.setClient` before `net.open({ join })`.
- **A hidden pane runs no frames**, so a two-tab test steps each tab in turn with `loop.advance` and walks the guest with `net.setTestSnapshot`. **On the wire an unpaused tab runs in real time even with no frames** (`loop.setBackgroundDriver`), so a scripted test pauses both tabs first. **A background tab's timers are throttled** (after five minutes hidden, to one wake a minute), so a two-tab script steps in a plain loop, yields through a `MessageChannel` rather than `setTimeout`, and joins with no `&lag=`.
- **A guest's own held-out pose** (#122, which could not be reproduced on 2026-10-18): both tabs on `setInterval(() => __game.loop.advance(1 / 60), 16.67)` (real time, the pane being hidden), the guest recording `[player.presentFor, player.anim.name]` each step; on the host `(await import("/src/entities/player.js")).eat(guestRecord, { hunger: 20 })` with the record's hunger below full. The guest's own player showed `present` for 34 of the 36 steps of `presentTime` (0.6 s): `presentFor` is a number in the light record, applied to the guest's own player like its hunger. A stepped-in-turn test (the host's 30 steps, then the guest's) shows a ragged tail, which is the test, not the game.
- A test that queues many guest inputs before a press must step the host through the queue. A fire's fuel reaches a guest at every whole unit burned, so a replica's fuel is compared to the unit. A frame's weight is measured from `net.status().wire` (the socket's bytes), never guessed.
- **Stepping away:** `__game.away.after(ms)` shortens the five minutes, `away.now`, `away.step()`, `away.back()`.
- **A server world locally:** `server/CLAUDE.md`; a dropped guest is at the title and the reload is the way back in after the world went.
