# 31.01 — The breadcrumbs: what the docs already say about more than one player

**Status, 2026-10-13: history.** The trail as it stood before any of the plan was built; every thread here has since been taken up, and `05` and `06` say how. Since this was written: the tiebreaker (entry 1) is replaced by the rule that every change is built for multiplayer in the same commit (`02`'s top entry, `08`); the save (13) is built as the worlds store (`09`); the creation screen (12) is the identity editor of `09`; death (11) now offers a new character in the same world (`09`), with the body's turning still owed; sleep's veto (6) is ruled, everyone in bed (`02`); the singletons of `23a` D8 (5) are on the player.

Collected 2026-10-13 from every doc. Each entry says where it is, what it says, and what it commits the game to. Nothing here is new; it is the trail this folder follows.

## The rulings that bind

1. **The tiebreaker** (`CLAUDE.md`, "Rules that are easy to forget"; `02`, 2026-10-12 "A tiebreaker for single-player forks"). When a single-player choice forks and one path favours a second human player while the other bakes in the single perspective (one global player, a sim that freezes or pauses as a whole, world changes made by poking state, randomness or wall-clock time inside the simulation, UI state tangled into the world's), all else equal take the multiplayer path. It only breaks ties; it never justifies building multiplayer early; a commit that was decided this way says so. **Commits the game to:** nothing being built now, and the fork list above being the checklist every new feature is read against. This folder's `05` is that list made concrete.

2. **The feasibility note** (`05-someday.md`, "Co-op: a second human player", 2026-10-12). Verdict: feasible, large, Zomboid's glitch avoidable by design; single player first; doors kept open. Lists what helps (a fixed 60 Hz step, deterministic growth from the seed, one character model with ids, a small map-mutation surface, the renderer and light per client, slow dead), what blocks (the player singleton with about ten places that matter, no server, hit-stop freezing game time, props without ids, every world change needing to become a command), the design (one authority, because Zomboid hands each zombie to the nearest player and two players fighting one flip its owner), five tiers by size, two transports (WebRTC with a copy-paste handshake, or a WebSocket relay beside `serve.py`), the cheap test (two tabs with 80 to 120 ms of delay once tiers 1 and 2 exist), and **the free rules**: no `Math.random` or `performance.now` in the sim, every world change through a mutator or an event, ids on everything that moves, the player passed never reached for, no feature that freezes the whole sim, each player's UI state apart from the world's. **Commits the game to:** one authority. This folder does not reopen that; `04` works it out.

3. **One generator and one clock** (`02`, 2026-10-12 "The simulation gets one generator and one clock"; `23` step 2 group C; `src/rng.js`, `src/loop.js`, `src/rules.js`). The first fork the tiebreaker decided: the sim rolls only through `rng.js` (seeded from the map's `seed`, default 1), reads time only through `loop.simTime()`, and the rules it reads from the settings are a snapshot "so a host could hand a guest the same object". Exempt by design: the embers and smoke in `fire.js`, the wild's position-keyed `hash2`, the renderer's animation clocks. Proved by `check("determinism")`: two boots, one hash over 71 entities. **Commits the game to:** a sim that can be replayed, which is what a replica or a drift check needs. `02` here says what the check does and does not cover.

4. **The controller from a snapshot** (`23` step 2, D1 and F; `src/player-controller.js:4-6`). `controlPlayer(player, zombies, dt, snapshot)` never touches the input module, "the co-op tiebreaker: a second player's snapshot could come from a wire"; the interface runs from `render()` on sim-time deltas, never from the step. **Commits the game to:** input as data. The audit finds the three sim files that still read the keyboard directly.

5. **The per-player singletons, named** (`23a` D8, 2026-10-12; `23` step 2's co-op check). "The singletons that are really per-player state move onto the player too: `archery`'s draw, marker, recover list, and aim override; `combat`'s `time` and `fx`; `light`'s one carrier (a list of carriers, one per player and burner); `placement.state`; `camera.cam`. Each is read through the player it belongs to, so a second player is a second object, not a second module. Done file by file as step 2 touches each, never as a pass of its own." `02`'s step-2 entry lists what was done (the controller, rules, rng, sim time, corpses and sleepers with ids); the singletons above were not reached. **Commits the game to:** the list; `05` here carries it.

6. **Sleep fast-forwards the simulation** (`30` law 6 and 3.3; `02` "The big pass answered"). Sleep is a loop speed multiplier with the world simulated at that speed, "decided by the co-op tiebreaker: the sim runs, nothing is poked"; 3.3's co-op note: "nothing here reads a global player; the fast-forward is a loop speed multiplier that a second player's presence would veto, not a clock jump." **Commits the game to:** time scale as a property of the world, and a rule for who can veto it. `03` here proposes the rule.

7. **The text log is a chat log with one player in it** (`02`, 2026-10-12 "Build in every right-click menu, Use on every item, and a text log"). "A list of lines, nobody's view of state, which is the shape a second player slots into (the co-op law, noted)." **Commits the game to:** the log as the chat.

8. **Everything is data** (`30` law 1). A rate, a recipe, an interaction, a fuel, a weapon's kills, a crop's days: a row in `data/`, never a branch in code. **Commits the game to:** the data files being the same on every machine, so only state travels, never rules. The host's data is the truth; a client with different data is refused (`04`).

9. **Nothing waits for art**, every new thing a placeholder through the same sheet interface (`30` law 7). **Commits the game to:** a remote player's figure being bakeable from data on any client, which the audit confirms the figure code can do.

10. **The records beyond the active region** (`03-world-model.md`: active radius 2, records hopping, alarm, lure, trickle; not built, "a milestone of its own"). Everything in it is centred on "the player's chunk". **Commits the game to:** nothing yet, which is the point: when it is built it must be built around a set of players, or it bakes in the single perspective harder than anything else in the game. `05` here says how.

11. **Death turns you; the next survivor arrives elsewhere with the kit** (`02`, 2026-10-08; `30` 3.5: the inn, the toll house, or the croft by turn; the cozy parent's `docs/18-death-and-survivors.md`). Today death is a dead screen and a page reload (`02`, 2026-10-10 night; `main.js:431-437`). **Commits the game to:** a death that keeps the world running, which with a second player in it is not optional. `03` here.

12. **The character creation screen** (`02`, 2026-10-10 night, pin 5: "look, hair, facial hair, the painted layers, on the settings screen's pattern"; `TODO.md`'s "next, in order" item 5; `12`: "the creation screen is next in this line"). Not built. **Commits the game to:** a player's look being chosen, which in multiplayer is the join screen and the thing that travels first. `03` here.

13. **Saves** (`10`: "nothing is saved yet"; `02` 2026-10-10: Save game disabled on the pause menu; `23` Q2b: saves behind the loading shell; `23a` D8: "then the save system (the parent's, later) has a shape to serialise"; the cozy parent's `docs/15-save-load.md`: one slot, versioned, each module its own `serialize()` and `restore()`, a snapshot that does not fit is discarded whole). **Commits the game to:** a serialisation per module. `04` here says the join is a load.

14. **The game runs in real time while its window is visible; a hidden tab stops** (`00`, playtest signals; `loop.js` on `requestAnimationFrame`). **Commits the game to:** a question: whose window? A listen server in a hidden tab stops the world for everyone. `04` here.

15. **Goobers** (`00`): the same body for everyone, gender from dress and hair, they and them in the text. **Commits the game to:** a creation screen with no body choices, which keeps it small.

16. **The figure sheets are the atlas's budget** (`02`, 2026-10-12 "The loading shell built"; `19` Status: about seventeen more distinct outfits; `23` Q2d: a second page "a day when it is needed"). **Commits the game to:** a sheet per player on every client, and the second atlas page becoming due with the first group of friends who dress differently.

17. **Villagers never fight for the player; swings pass through the living** (`04`, `19`). **Commits the game to:** a precedent for players: no friendly fire, the swing passes through a person.

18. **The OSRS rule** (`30` law 2; `02` "Build in every right-click menu"): the verb is on the thing, out-of-range actions auto-walk, Use is an item then a target. **Commits the game to:** every player action already having the shape of a command (a verb, a target, an argument) with the walk as part of it, which is how Old School RuneScape itself is served: the client sends intents, the server walks you and acts. `04` leans on this.

## The things that were said in passing

- `29-world/10` item 21 and `30` section 12 list the records milestone as large and its own; `29/08` places about 120 authored dead and fourteen villagers. Those are the counts a replica sees at most: small on the wire (`04`).
- `23`'s performance section: fifteen times headroom in the frame; the real per-frame cost is things that move, think, light, or touch the DOM. A second player costs one more of each.
- `23a` H: the pure modules already run under plain Node (`tools/check.js`: `rng`, `clock`, `bleed`, `infection`, `items`, `pathfind`); what blocks a headless run of the core is `document` in `assets.js` and the pixel pick in `interact.js`, and the renderer's calls into the map. That is the whole gap between "a sim" and "a server".
- `02` 2026-10-10: "The dead kill. Death stops the game on a dead screen... the one way out is back to the title, which is a fresh load of the page." Fine alone; not with a friend in the world.
- `02` 2026-10-10 night: settings live in the browser, not in a save. The audit sorts them into the ones that are rules of the world (the host's) and the ones that are a viewer's (`02` here, section 8).
- `21`: a tap is a press released within 0.2 s of simulation time, counted in steps. A command stream keeps that rule where it is: the client counts, the authority receives "tap" or "hold".
- `20`: hits are checked at landing only; the arrow's flight is deterministic from its launch. The cleanest possible thing to send (`03`).
- `14`: the swing resolves on the click, the animation is cosmetic, the cooldown is the rate limit (the parent's rule, kept). A swing is therefore one message, not a held state (`03`, `04`).
