# Bugs fixed from the wiki census, 2026-10-14 and 15

**What this is:** the Fixed section of `docs/bugs.md` as it stood on 2026-10-16: the 27 items from the wiki census (read in the code at `9205ad7`) fixed on 2026-10-14 and 15, one line each with the commit that fixed it, moved here whole by the sweep, 2026-10-16, and never edited after. The live file is `docs/bugs.md` (Open, Became issues, what is fixed since, Closed). Where a line said "the commit that moves this line" or "the same commit", the commit is named at the line's end, resolved from `git log --follow -- docs/bugs.md` and confirmed against each commit's message.

## Fixed

- [x] **On a Windows checkout the data validator and the manifest disagree about line endings** (added 2026-10-15 by a Secondary, reproduced, at `826e53c`): with `core.autocrlf` on, `python -I tools/validate-data.py` hashes the files as they are on disk (CRLF) and reports 12 manifest entries as changed (`interactions.json`, `poses.json`, `valley.json`, the cursors' files, two layer indexes, and more), because those entries were stamped from the repository's LF copies while others (`items.json`) were stamped from CRLF copies. `tools/manifest.py` and the validator should hash the bytes as git stores them (CRLF to LF for text), or the repository should carry a `.gitattributes` with `* text=auto eol=lf`, so the stamps agree on every machine and on the deployed site. **Fixed by Primary (2026-10-15, the commit that moves this line; no issue, the GitHub setup not done yet):** `tools/manifest.py` and the validator stamp a text file (`.json` and the like) with its line endings as LF, as git stores it, and a picture by its bytes, so every machine and the deployed site stamp alike; every JSON stamp checked equal to git's stored bytes. A running `serve.py` imports the manifest tool, so it takes the change when restarted. Commit `a11a98e`.
