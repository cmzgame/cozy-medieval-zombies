# `server/`: the relay and the server worlds

Read with the root `CLAUDE.md` and `src/CLAUDE.md` (the wire is `src/net.js`; the authority's half shared by a browser host and a server world is `src/host.js`). The design and its rulings: `docs/31-multiplayer/04` (status), `09`, and `docs/02` 2026-10-13 to 15. **Only Michael touches a secret, a repository setting, or anything on Fly** (`github.md`, section 2).

- `relay.js`: a Node WebSocket process with no dependency, the lobby and the pipe for friends anywhere (`wss://cmz-relay.fly.dev` in production; `node server/relay.js 8012` locally, the app's `relay`). It answers `GET /open?code=` for the Worlds screen's dot and Rejoin's wait, limits lookups per address, and its front page names its build. **As the worlds' keeper** (with `DATA_DIR` set): keeps the server worlds under `DATA_DIR/worlds/<worldId>/` (`meta.json` holds the code's SHA-256, never the code), starts a world's process when a guest names its code (one per world, at most `CMZ_MAX_RUNNING`, three by default), reserves the code for its own child (`CMZ_HOST_SECRET`), and asks every world to save and stop on a signal. Its endpoints for the owner's powers, opened by the owner key: `POST /worlds` (Move to the server, with the creator key `CREATOR_KEY`; CORS for `CMZ_SITE_ORIGIN` and localhost alone; 4 MB compressed, 64 MB unpacked, restored before accepted), `/worlds/home` and `/worlds/home/confirm` (Bring it home, two phases with a token; the server's copy to the trash only then), `/worlds/owner`, `/worlds/rotate`, `/worlds/rules`, `/worlds/remove` (the removed player's browser barred until let back in), `/worlds/unbar`, `/worlds/rekey` (a lost key replaced with the creator key). Caps: `CMZ_MAX_WORLDS`, `CMZ_UPLOADS_PER_HOUR`. `CMZ_DEBUG=1` opens `/debug/worlds`, naming each world's debug port.
- `world.js`: one world headless from its gzipped save, joining the relay as its host with the same `net.js` and `host.js` a browser host uses; held when empty, stopped and saved after a spell empty (`--empty-exit <s>`, `CMZ_EMPTY_EXIT`); saves every five game minutes while played and at every join, leave, and empty spell, rolling copies at most every ten minutes (three kept) and daily (seven kept), a crash to `crash-<time>.json.gz` and never over the good save; the welcome gzipped. `node server/world.js --dir <folder> --code <code> --relay ws://localhost:8012 [--new] [--empty-exit <s>] [--debug-port <p>]`; the debug endpoint (`/status`, `/sync/on`, `/sync`, `/stop`) on 127.0.0.1 alone and only when asked for. A server world refuses a page of another build (the build id, compared only when both are stamped).
- `worlds.js`: `node server/worlds.js new --data <dir> --name <n>` makes a world and prints its code once.
- `boot.js`: the data stage under Node, JSON alone, shared with `tools/world.js`.
- **The deploy:** `.github/workflows/deploy.yml` deploys the relay and its server worlds to Fly on every push to `main` (the secret `FLY_API_TOKEN`; the app `cmz-relay`, region `ord`, one 512 MB machine that stops when idle), stamping the commit as the build id (`Dockerfile` `CMZ_BUILD_ID`, the page's `src/build.js`), and publishes the site to GitHub Pages stamped the same. The image is `server/`, `src/`, and `data/`'s JSON (`.dockerignore`); the worlds live on the Fly volume `cmz_data` at `/data`.
- **A local test:** `DATA_DIR=<dir> CMZ_DEBUG=1 CMZ_EMPTY_EXIT=20 CREATOR_KEY=<k> node server/relay.js 8013` (the relay passes its environment to each world it starts), tabs on `?nosave&relay=ws://localhost:8013`, a guest given its own browser id with `net.setClient` before `net.open({ join })`; a world made on a `?nosave` tab keeps its worlds and keys in the page's memory. `docs/testing.md` has the two-tab habits.
