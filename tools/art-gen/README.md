# `tools/art-gen/`: the design agent's art generators, an archive

**Kept, not run** (Michael, 2026-10-16, #95: "Keep this around but I will probably not use them often if ever"). These are the Python scripts (numpy and PIL) that Claude Design wrote to draw the art in `data/art/`, copied out of its delivery zips so they are not lost with Michael's downloads. They are a record, read and never run without Michael (`docs/27`; the root `CLAUDE.md`: delivered art is data, read and never run). Running one would write fresh PNGs and anchors over art the game already uses, so a re-roll, a recolour, or a new wall height is Michael's call, in a session that names what it will overwrite. No work is planned on them: a "spiff up the tools" pass is for much later, after most of the gameplay (#106, the someday tracker).

`character/` is the character painting scripts, committed earlier and untouched here. Everything else came in on 2026-10-16, copied as delivered, byte for byte, with no edits. Only the scripts and the docs that say how they were used came in: no PNGs (the art is in `data/art/`) and no previews. Every file was read before it was committed; none makes a network call, starts a process, or touches anything outside its own `out/` folder (the one deletion, in `pumpkin2.py`, clears its own old `jackolantern*` files from `out/pumpkin/`).

## How they were laid out

Each script expects every other one beside it in one flat folder and writes under `out/<set>/` next to itself (`D = os.path.dirname(__file__)`). They import one another across these folders (`decals.py` and the previews import `trees_v2`; the previews import `decals.grass_field`; `farm_water.py` imports `ground`; `crops.py` imports `pumpkin2`; `furniture.py` imports `village`), so none of them runs from where it sits here, which suits an archive.
